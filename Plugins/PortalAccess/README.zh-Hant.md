# PortalAccess：傳送門互動恢復

F12 → 刷圖與收益 → 傳送門交互恢復 → 開啟「恢復傳送門交互」。嘗試恢復目前區域仍然存在、但已關閉的門的互動與高亮。新設定預設關閉，保留使用者已儲存的選擇。

目前支援於 2026-10-05、2026-10-06、2026-10-10 驗證的三版客戶端結構，並依符合的版本選擇元件虛表。必須同時符合四段遊戲程式碼的摘要、元件虛表與客戶端除錯文字對應的欄位，才允許寫入 0x69、0x6A 兩個布林值。舊 0x51/0x52 偏移位於指標內部，不再用於遊戲寫入。版本不符時自動退回唯讀狀態。

每次寫入前檢查原生載入計時、區域位址與編號、玩家身分、傳送門元件歸屬及條件。同一扇門在同一區域只恢復一次；切區時捨棄舊位址。關閉開關會嘗試撤銷本插件對目前有效門的修改。一般記憶體寫入介面仍然只允許離線測試操作自己的程序。

掃描共用 15 毫秒、4,000 次讀取預算，每頁最多走訪 2,000 個節點，最多保留 128 扇門。恢復另設 40 毫秒截止時間，檢查之間若已逾時就停止寫入。診斷每 10 秒儲存至 config，可以查看符合的版本、修改欄位數量及目前的門狀態。

已對正在執行的客戶端及關閉的門完成唯讀匹配驗證，門的顯示及實際進圖效果由使用者繼續測試。無法重新建立已刪除的門，也不能保證已過期或被伺服器拒絕的地圖可進入。技術證據見 [DIAGNOSTIC_LAYOUT.md](DIAGNOSTIC_LAYOUT.md)；[離線測試](../../Tests/README.md) 不寫入遊戲。

掃描已改為按實體編號分批繼續，每張表每次最多處理 128 個實體；不儲存跨次走訪指標，切區後重設。已找到的門會保留並優先複查，避免掃描耗盡預算後遺失。新版診斷包含掃描總量、目前位置及停止原因。Steam 日誌已通過程式碼版本驗證，先前停在掃描未完成階段；本次修復待朋友實測。
