# PortalAccess：传送门交互恢复

F12 → 刷图与收益 → 传送门交互恢复 → 开启「恢复传送门交互」。尝试恢复当前区域仍然存在、但已关闭的门的交互与高亮。新配置默认关闭，保留用户已保存的选择。

目前支持在 2026-10-05、2026-10-06、2026-10-10 验证的三版客户端结构，并按匹配版本选择组件虚表。必须同时匹配四段游戏代码的摘要、组件虚表和客户端调试文字对应的字段，才允许写入 0x69、0x6A 两个布尔值。旧 0x51/0x52 偏移位于指针内部，不再用于游戏写入。版本不匹配时自动退回只读状态。

每次写入前检查原生加载计时、区域地址与编号、玩家身份、传送门组件归属和条件。同一门在同一区域只恢复一次；过图时丢弃旧地址。关闭开关会尝试撤销本插件对当前有效门的修改。普通内存写入接口仍然只允许离线测试操作自己的进程。

扫描共用 15 毫秒、4,000 次读取预算，每页最多遍历 2,000 个节点，最多保留 128 个门。恢复另设 40 毫秒截止时间，检查之间若已超时就停止写入。诊断每 10 秒保存到 config，可以查看匹配的版本、修改字段数量和当前门状态。

已对正在运行的客户端和关闭的门完成只读匹配验证，门的显示及实际进图效果由用户继续测试。不能重新创建已删除的门，也不能保证已过期或被服务器拒绝的地图可进入。技术证据见 [DIAGNOSTIC_LAYOUT.md](DIAGNOSTIC_LAYOUT.md)；[离线测试](../../Tests/README.md) 不写入游戏。

扫描已改为按实体编号分批继续，每张表每次最多处理 128 个实体；不保存跨次遍历指针，切图后重置。已找到的门会保留并优先复查，避免扫描耗尽预算后丢失。新版诊断包含扫描总量、当前位置及停止原因。Steam 日志已通过代码版本校验，之前停在扫描未完成阶段；本次修复待朋友实测。
